## ۱. نمای کلی معماری و زیرساخت (Architecture Overview)

سیستم **HSECORE AI** به عنوان یک زیرساخت کاملاً محلی (On-Premise / Local)، مستقل، امن و بدون هرگونه وابستگی به APIهای پولی یا سرویس‌های ابری خارجی پیاده‌سازی شده است. در حالت استنتاج محلی، درخواست‌ها به موتور خارجی ارسال نمی‌شوند؛ دریافت اولیه/به‌روزرسانی ایمیج Ollama و مدل‌ها نیازمند دسترسی خروجی اینترنتی است.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        مرورگر کاربر (Web Client)                       │
│    • ماژول چت هوشمند کاربری (RTL / React 19)                           │
│    • پنل مدیریت هوش مصنوعی در تنظیمات سیستم                           │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ HTTPS (پورت 443 / 3000 داخلی)
┌───────────────────────────────────▼────────────────────────────────────┐
│                    بک‌اند سازمانی (HSECORE Node/Express)                │
│    • دروازه امنیتی (AISecurityService - فیلتر نفوذ و سانسور اسرار)     │
│    • صف کنترل همزمانی (AIRequestQueue - حداکثر ۱ استنتاج همزمان)       │
│    • ارکستریتور دستیاران ۱۰گانه (AIOrchestrator)                        │
│    • موتور RAG و پایگاه دانش سازمانی (AIRagService)                    │
│    • ابزارهای مجاز واکشی داده (AIToolsRegistry - فقط‌خواندنی)           │
└──────────────────┬─────────────────────────────────┬───────────────────┘
                   │ SQL (Drizzle ORM)               │ HTTP داخلی (شبکه داکر)
┌──────────────────▼─────────────┐ ┌─────────────────▼───────────────────┐
│      پایگاه داده PostgreSQL     │ │       موتور استنتاج محلی Ollama     │
│ • جداول اصلی سامانه HSECORE    │ │ • کانتینر ایزوله `hse-ai-engine`    │
│ • جدول `ai_knowledge_docs`     │ │ • سقف: ۴ هسته CPU / ۴ گیگابایت RAM  │
│ • جدول `ai_knowledge_chunks`   │ │ • والیوم پایدار: `hse_ai_models`    │
└────────────────────────────────┘ └─────────────────────────────────────┘
```

## ۲. مشخصات سخت‌افزاری و تخصیص منابع VPS

* **مشخصات سرور هدف:** Ubuntu 24.04 LTS (8 vCPU, 8GB RAM, 50GB SSD)
* **سقف مصرف موتور هوش مصنوعی:** حداکثر **۴ هسته CPU** و **۴ گیگابایت RAM**
* **حفاظت ضد کرش (Anti-OOM):** صف‌بندی استنتاج با ظرفیت همزمانی ۱ (`maxConcurrency = 1`) و مهلت زمانی ۶۰ ثانیه.
* **مدل اولیه پیشنهادی برای ارزیابی در فاز انتخاب مدل:** `qwen3:1.7b` (حجم فایل رسمی حدود ۱.۴ گیگابایت؛ این مقدار با RAM مصرفی زمان استنتاج یکسان نیست و باید روی VPS اندازه‌گیری شود).
* **مدل برداری RAG:** `bge-m3` (حجم فایل رسمی حدود ۱.۲ گیگابایت؛ دریافت آن در مرحله مدیریت مدل انجام می‌شود).

## ۳. راه‌اندازی موتور محلی و مدیریت مدل‌ها

**فاز دوم فقط زیرساخت Runtime را راه‌اندازی می‌کند:** ایمیج Ollama با تگ ثابت `0.34.0`، شبکه مشترک Docker، Health Check و Volume پایدار. در این مرحله مدل گفت‌وگو یا Embedding دانلود نمی‌شود. سرویس HSECORE به موتور AI وابستگی اجباری ندارد و می‌تواند مستقل اجرا شود.

API موتور فقط روی شبکه داخلی Docker در دسترس است؛ هیچ پورت میزبان برای ۱۱۴۳۴ منتشر نمی‌شود. دریافت/به‌روزرسانی ایمیج Ollama و مدل‌ها به خروجی اینترنتی VPS نیاز دارد، اما درخواست‌های استنتاج و اتصال Backend به Ollama داخلی باقی می‌ماند.

برای نصب Runtime از گزینه ۸ منوی `install.sh` یا دستور زیر استفاده کنید:

```bash
sudo ./scripts/setup-local-ai.sh
```

این دستور نیازمند حداقل ۶ گیگابایت RAM میزبان و ۸ گیگابایت فضای آزاد برای شروع است و پیش از راه‌اندازی منابع را بررسی می‌کند. پس از آماده‌شدن Runtime، انتخاب و دانلود مدل در مرحله مستقل مدیریت مدل انجام می‌شود.

### دستورات مدیریت Runtime و مدل‌ها

برای مدیریت زیرساخت هوش مصنوعی، اسکریپت اصلی نصب با منوی گزینه ۸ یکپارچه شده است:

```bash
sudo ./install.sh
# انتخاب گزینه 8: Local AI Infrastructure (HSECORE AI)
```

## ۵. امنیت، محرمانگی و سطوح دسترسی (RBAC)

1. **اصل دسترسی کمینه (Fail-Closed):** در صورت عدم احراز هویت یا فقدان مجوز کاربر، درخواست مسدود می‌شود.
2. **فیلتر تزریق پرامپت (Prompt Injection Defense):** کلیه عبارات تلاش برای افشای پرامپت، تغییر نقش مدل یا کدهای مخرب قبل از ورود به موتور مسدود می‌گردند.
3. **ماسک‌سازی اسرار (Token Redaction):** کلیدها، توکن‌های JWT و گذرواژه‌ها به صورت خودکار با عبارت `[اطلاعات محرمانه مسدود شد]` جایگزین می‌شوند.
4. **عدم تولید SQL مستقیم:** هوش مصنوعی هرگز کوئری مستقیم SQL روی دیتابیس اجرا نمی‌کند. تمام ارتباطات از طریق توابع فقط‌خواندنی Drizzle ORM کنترل می‌شود.
5. **ایزولاسیون شبکه:** پورت ۱۱۴۳۴ هرگز در اینترنت منتشر نمی‌شود و صرفاً در شبکه داخلی داکر فعال است.

## ۶. نگهداری، پشتیبان‌گیری و بازیابی (Disaster Recovery)

* **ماندگاری مدل‌ها:** فایل‌های مدل‌ها در والیوم پایدار داکر `hse_ai_models` ذخیره شده‌اند و با آپدیت نرم‌افزار حذف نخواهند شد.
* **پشتیبان‌گیری از متادیتا و اسناد RAG:**
  جداول `ai_knowledge_docs`، `ai_knowledge_chunks` و `ai_chat_sessions` در پایگاه داده اصلی PostgreSQL ذخیره شده و به همراه نسخه پشتیبان دوره‌ای سامانه (`backup_database` در `install.sh`) ذخیره و بازیابی می‌شوند.
* **بازیابی سریع:**
  در صورت بروز هرگونه مشکل برای کانتینر هوش مصنوعی، می‌توان با دستور زیر کانتینر را بدون تغییر در هسته نرم‌افزار بازسازی کرد:
  ```bash
  sudo docker compose -f docker-compose.ai.yml up -d --force-recreate hse-ai-engine
  ```
